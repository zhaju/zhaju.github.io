## 2.2 | How ARM64 Executes Programs
```
PC = 0x00 // start at address 0
while True do // infinite loop
	IR = MEM[PC] // fetch the 32 bit halfword in PC, put it in IR
	NPC = PC + 4 // compute the next PC (next halfword)
	Decode and execute instruction in IR
	PC = NPC // repeats the loop
```

Fetch-execute cycle
- NPC = next PC (Program Counter) value
	- Usually PC + 4 (next byte / halfword)
	- We run instructions in order: 0,4,8,12, etc.

### Loading Constants (PC-Relative Load)
Load-and-skip pattern
- Instructions are in memory, and read values from somewhere else in memory
- **PC-Relative Load**
- `xd = MEM[PC + i*4]`
- Take a word near the PC, copy it into a register (xd) $i$ halfwords (4i bytes) after the PC
	- If $i=0$, this copies the instruction + next halfword into xd

Load $11(1011_2)$ into x8
```
01011000iiiiiiiiiiiiiiiiiiiddddd
vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv
vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv

01011000000000000000000000101000
(opcode)				  (01000) = destination x8
00000000000000000000000000001011
						  (01011) = value 11
00000000000000000000000000000000  = all 0s because a word is 64 bits
```

Does this work?
- Almost: It loads 11 into x8, but remember the **fetch-execute cycle**
- It tries to run 11 as an instruction, which will crash
- Problem: Our data has to be near the PC to load, but we can't run it as code
- Solution: We need a second instruction to **skip** the data

Branching = skipping or jumping code in ARM64
- Branch Instruction: `NPC = PC + i*4`
- This means "skip i instructions" (including the PC itself)

```
01011000iiiiiiiiiiiiiiiiiiiddddd
vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv
vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv

01011000000000000000000000000011
						  (00011) = branch 3 halfwords past value
00000000000000000000000000001011
						  (01011) = value 11
00000000000000000000000000000000
(next instruction..............)
```

We combine PC-relative load and branch to make the **load-and-skip pattern**
- 1st halfword: PC-relative load from 3rd, 4th halfword
- 2nd halfword: Branch past 3rd, 4th halfword
- 3rd, 4th halfword: the data

```
00000000000000000000000000000000
```

## 3.3 | Regular Languages
Deterministic Finite Automata (will draw on exams)
- An arrow into the initial start state
- Accepting states are two circles
- Arrows from state to state are labelled
- Error state(s) are implicit (a common “hack”)

> Regular Language over alphabet $\Sigma$
> 1. Empty language and the language consisting of the empty word are regular
> 2. All languages $\{a\}$ for all $a\in\Sigma$ are regular
> 3. The union, concatenation, or Kleene star of any two regular languages are regular
> 4. Nothing else

If $L, L_1,L_2$ are regular languages, then so are the following
Union
$$
L_1\cup L_2=\{x:x\in L\text{ or } x\in L_2\}
$$
Concatenation
$$
L_1\cdot L_2=L_1L_2=\{xy:x\in L1, y\in L_2\}
$$
Kleene star: infinite combination of union and concatenation
$$
L*=\{\epsilon\}\cup\{xy:x\in L*, y\in L\} = U_{n=0}^\infty L^n
$$
Operator Precedence
$$
a*b > ab > a\cup b
$$

Let $\Sigma=\{a,b\}$. Explain why $L=\{ab^na:n\in\mathbb{N}\}$ is regular
- Regular languages are closed under Kleene star, so $\{b\}*$ is regular
- Concatenation of regular languages are also regular, so $\{a\}\cdot\{b\}*\cdot\{a\}$ is regular

Regular Expressions
- Notation
- Union
- Concatenation
- Kleene star
- Order of operations

**Deterministic** finite automata
- Every state has one transition for each $c\in\Sigma$ 
- Including the ERROR state if there is one
- NFA (nondeterministic) can have multiple transitions per character
- $\epsilon-NFA$ can consume no character
## 3.4 | DFAs
> A DFA is a 5-tuple ($\Sigma, Q, q_0, A, \delta$)
> - $\Sigma$ = finite non-empty set (alphabet)
> - Q = finite non-empty set of states
> - $q_0\in Q$  = start state
> - $A\subseteq Q$ = set of accepting states
> - $\delta:(Q\times\Sigma)\to Q$ = total transition function (given a state and symbol, what state should we go to)

> Language of a DFA = the set of all strings accepted by w
$$
L(M)=\{w:M\text{ accepts } w\}
$$
> Theorem (Kleene)
> L is regular if and only if $L = L(M)$ for some DFA M. That is, the regular languages are precisely the languages accepted by DFAs
## 3.5 | Back to scanning
General idea: Consume the largest possible token that makes sense. Produce the token and then proceed.
- Maximal Munch: Consume characters until you no longer have a valid transition. If you have characters left to consume, backtrack to the last valid accepting state and resume.
- Simplified Maximal Munch: Consume characters until you no longer have a valid transition. If you are currently in an accepting state, produce the token and proceed. Otherwise go to an error state.

```
Tokens:

bbbb

Input:

```

# 5 | Regular Languages Continued (NFAs)
## 5.1 | NFAs
Extending $\delta$ (transition function)
- $\delta:(Q\times\Sigma)\to Q$ to a function defined over $(Q\times\Sigma*)$ via:
$$
\begin{align}
\delta*&:(Q\times\Sigma*)\to Q \\
&:(q,\epsilon)\to q \\
&:(q,aw)\to\delta*(\delta(q,a),w)
\end{align}
$$
- where $a\in\Sigma$ and $w\in\Sigma*$ ($aw$) is concatenation
- Basically, process a letter first then process the rest of the string

> Definition
> A DFA given by $M=(\Sigma, Q, q_0, A, \delta)$ **accepts a string** $w$ if and only if 
$$
\delta*(q_0,w)\in A
$$

Warm-up: Write a regex for words that start and end with the same pair
$$
aa(a\mid b)*aa\mid bb(a\mid b)*bb\mid ab(a\mid b)*ab\mid aa\mid bb\mid aaa\mid bbb
$$

NFA: Suppose we allowed more than one transition from a state with the same symbol
- $\delta(Q\times\Sigma)\to2^Q$ is our (total) transition function
- Note that $2^Q$ denotes the power set of q, that is, the set of all subsets of $Q$
- This allows us to go to multiple states at once

$$
\begin{align}
\delta*(2^Q\times\Sigma*)&\mapsto 2^Q \\
(S,\epsilon)&\mapsto S \\
(S,aw)&\mapsto\delta*(\bigcup_{q\in S}\delta(q,a),w)
\end{align}
$$
Decision Problems / P = NP
- Polynomial vs Nondeterministic Polynomial
- Currently, we only know how to track nondeterminism in exponential $(2^n)$, not polynomial runtimes

NFA: Track every path in a set $S\in2^Q$
- If your set of final states after processing $\epsilon$ contains an accepting state, accept

NFAs are not more powerful than DFAs
- One could write down all of the $2^Q$ possible states and connect each one
- More simply, go through the NFA and determine what happens for each character on each state
- Each subset $S$ is its own state
- NFA has $n$ states, DFA has $2^n$ (time vs space tradeoff)

## 5.2 | Context-free grammars
> **Context Free Grammar (CFG)** is a 4-tuple $(N,\Sigma, P, S)$
- $N$ = finite non-empty set of non-terminal symbols
- $\Sigma$ = alphabet, set of non-empty terminal symbols
- $P$ = finite set of productions, each of the form $A\to\beta$ where $A\in N, \beta\in(N\cup \Sigma)^*$
- $S\in N$ is a starting symbol

Conventions
- $a,b,c\ldots$ = terminals (symbols or characters) from $\Sigma$
- $w,x,y,\ldots$ = words (strings) from $\Sigma*$
- $A,B,\ldots,S,\ldots$ = non-terminals (variables) from $N$
- $S$ = start symbol, a non-terminal from $N$
- $\alpha,\beta,\gamma$ = words from $V*=\{N\cup\Sigma\}*$

Notations and terminology
- $\alpha\implies\beta$ = $\alpha$ derives $\beta$ in one step
- $\alpha\implies*\beta$ = $\alpha$ derives $\beta$ eventually
- $\alpha A\beta=\implies \alpha\gamma\beta$ = if there exists $A\to\gamma$ in $P$

Example
$\Sigma=\{(,)\}, L=\{w:w \text{ is a balanced string of parentheses}\}$
- $S\to \epsilon$
- $S\to(S)$
- $S\to SS$
$$
S\to\epsilon\mid (S)\mid SS
$$

Context-free languages can't understand this:
```cpp
long a;
(*a) + 12; // need context to know a is an int, so this isn't allowed
```

> Definition
> Language of a CFG
$$
L(G)=\{w\in\Sigma*:S\to*w\}
$$
> Definition
> A language is context-free if and only if there exists a CFG $G$ such that
$$
L=L(G)
$$
> All regular languages are context free!
## 5.3 | Arithmetic
Leftmost (rightmost) derivation = always substitute leftmost (rightmost) non-terminal

ex. arithmetic ops over $\Sigma=\{a, b, c, + , *, /, (, )\}$ 
CFG for $L_1$: arithmetic expressions from $\Sigma$ without parentheses, and derivation for $a-b$
- `S -> a|b|c|SRS`
- `R -> +|-|\*|/`
CFG for $L_2$: w balanced parentheses, and a derivation for $((a)-b)$
- `S -> a|b|c|SRS|(S)`
Derivation for $a-b*c$: 
- **Leftmost derivation** (always substitute leftmost non-terminal): `S => SRS => SRSRS => aRSRS => a-SRS => a-bRS => a-b\*S => a-b\*c`
```
        S
      / | \
     S  R  S
     |  |  |\ \
     a  -  S  R  S
           |  |  |
           b  *  c
```
- `S => SRS => S\*S => S\*c => SRS\*c => S-S\*c => a-S\*c => a-b\*c`
- **Rightmost derivation**: `S => SRS => SRSRS => SRSRc => SRS\*c => SRb\*c => S-b\*c => a-b\*c`
```
        S
      / | \
     S  R  S
     |  |  |\ \
     a  -  S  R  S
           |  |  |
           b  *  c
```
^ BUT could also be a leftmost derivation: `S => SRS => aRS => a-S => a-SRS =>* a-b\*c`
## 5.4 | Ambiguity
> Definition
> A grammar for which some word has more than one distinct leftmost derivation/rightmost derivation/parse tree is called ambiguous

Leftmost != rightmost derivation - the whole reason we have PEMDAS
```
S → a | b | c | SRS 
R → + | − | ∗ | /
```
$$
(a-b)\times c\neq a-(b\times c)
$$
For our compiler

    - 2 diff parse trees
    - 2 diff leftmost derivations
We want

    - **post-order traversal** (left -> right -> root)

    - S => SRS: problem - can extend expression by substituting either first or last S

## 6.4 | LL(1), formally
> LL(1)
> A grammar is called LL(1) if and only if each cell of the predictor table contains at most one entry.

$First(\beta)$: set of characters that can start a derived string starting from $\beta\in V*$
- $First(L\quad M) = First (L)$ (first terminal)

$Predict(A, a)$:  production rule(s) that apply when $A\in N$ is on the stack and $a\in\Sigma$ is the next input character
- Problem: $A\implies*\epsilon$

$Nullable(\beta)$: true iff $\beta\implies*\epsilon$ 
- $\beta\in V*$ is **nullable** if and only if $Nullable(\beta) = true$

$Follow(A)$: A character $c$ follows $A$ if it's possible to derive a string that has $Ac$
- Whatever follows the thing

> Predict
$$
\begin{align}
Predict (A,a) &= \{A\to \beta: A\in First(\beta)\} \\
&\cup\{A\to\beta: Nullable(\beta)+a\in Follow(A)\}
\end{align}
$$
## 6.5 | Nullable, First, and Follow
Nullable
- $Nullable(\beta)$ is false whenever $\beta$ contains a terminal symbol
- $Nullable(AB)=Nullable(A)\land Nullable(B)$

First
- Ignore **trivial productions** of the form $A\to\epsilon$
- $First(S')=\{\vdash\}$ always

Predict table = any number of iterations

**Cheat sheet and examples**
Nullable
- $A\in\epsilon$ implies $Nullable(A)$ and $Nullable(\epsilon)$
- If $A\to B_1\ldots B_n$ and each of $Nullable(B_i)$, then $Nullable (A)$

First
- $A\to aa$ then $a\in First(A)$
- $A\to B_1\ldots B_n$ then $First(A)=First(A)\cup First(B_i)$ until $Nullable(B_i)$ is false

Follow
- $A\to aB\beta$ then $Follow(B)=First(\beta)$
- $A\to ab\beta$ and $Nullable(\beta)$, then $Follow(B)=Follow(B)\cup Follow(A)$

$$
\begin{align}
Predict (A,a) &= \{A\to \beta: A\in First(\beta)\} \\
&\cup\{A\to\beta: Nullable(\beta)+a\in Follow(A)\}
\end{align}
$$

# 7 | Bottom-Up Parsing, LR(0), SLR(1)
## 7.1 | Bottom-up parsing
**Bottom-up parsing**
- Move through the word left to right
- If the string in "Read" matches a transition, reduce it with one of the rules
- Pop the string, push result onto stack
## 7.2 | The LR(0) oracle
> Knuth's Theorem
$$
\begin{align}
\{aa:a&\in V*\text{is a stack} \\
a&\in\Sigma\text{ is the next character} \\
\exists x &\in\Sigma*\text{ such that }  S\implies*aax\}
\end{align}
$$
> Is a regular language

> Item
> A production with a dot / bookmark $(\bullet)$ on the RHS of a rule, indicating a partially completed rule

**Automaton**
- One transition per box like a DFA/NFA
- Move the dot to the right
- Benefit: no ambiguity like bottom-up parsing (eg. with $\vdash Acdef$, do you pop $def$ or $ef$?)
## 7.3 | Efficient LR(0)
Time complexity
- Naive DFA approach that re-runs itself is $O(n^2)$
	- Changes are occurring at the top of stack, bottom remains unchanged
- Solution is to move through the DFA in a **state stack**, and push/pop to it the same time as the **symbol stack**, making the time $O(n)$

LR(0)
- Left-to-right
- Rightmost derivation
- 0 lookahead
## 7.4 | Bottom-up parsing conflicts
**Issue one (shift-reduce)**
- $A\to a\bullet a\beta$ (shift)
- $B\to y\bullet$ (reduce)

$B\to ab\bullet$
$A\to b\bullet c$
Stack: $ab$

**Issue two (reduce-reduce)**
- $A\to A\bullet$
- $B\to y\bullet$

$A\to c\bullet$
$B\to bc\bullet$
Stack: $abc$

> A grammar is LR(0) if and only if after creating the automaton, no state has a shift-reduce or reduce-reduce conflict
## 7.5 | SLR(1)
SLR = Simplified LR with 1 character lookahead

Follow sets (if statements): $Follow(S)=\{\dashv\}, Follow(T)=\{+,\dashv\}$
$$
S\to T\bullet +s\quad\quad\quad\quad S\to T\bullet:\{\dashv\}
$$
- If the next token is $+$, apply the first
- If the next token is $\dashv$, apply the second
- Else, ERROR

If $Follow(E)=\{+,\dashv\}$, then it's not SLR(1)
- $E\to T\bullet +E$
- $E\to T\bullet+\{+, \dashv\}$

```
add sp, sp, x8     // sp += 8

add sp, sp, x8
ldur x, [sp, -8]

code(expr1) // result in x0
push(x0)
code(expr2) // result in x0
pop(x1)
sub x0, x1, x0
```

```
		ldur x1, [x0, 0]       // x1 = value
		add x1, x1, x11        // x1 = x1 + 1
		stur x1, [x0, 0]       // store x0
		add x0, x1, xzr        // x0 = x1 + 1
	}
	if (node.rule is factor -> lvalue PLUS PLUS){
		code(node.children[0]) // x0 = &lvalue
		ldur x1, [x0, 0]       // x1 = value
		add x2 x1, xzr         // x2 = x1
		add x1, x1, x11        // x1 = x1 + 1
		stur x1, [x0, 0]       // store x0
		add x0, x2, xzr        // x0 = x2
	}
	ir (node.rule is statement -> lvalue PLUSBECOMES expr SEMI){
		code(node.children[0]) // x0 = &lvalue
		push(x0)               // store x0 on stack
		code(node.children[2]) // x0 = &expr
		add x1, x0, xzr        // x1 = x0 (expr)
		pop(x2)                // x2 = &lvalue
		ldur x0 [x2, 0]        // x0 = lvalue
		add x0, x0, x1         // x0 = x1 (expr) + x0 (lvalue)
		stur x0, [x2, 0]       // store x0
	}
}
```

NULL
- We want NULL to crash if we try to dereference it
- Can't be `0x0` because that's a valid memory address (C was designed to protect 0)
- We should pick a negative number so it won't be a valid memory address - start using signed ints
- If you pick `-1`, there might be problems if you try to `*(p+1) = *(0)`
- Pick a very high number like `0xFFFFFFFFFFFF0000 == -65536`
- **New convention:** `x6 = -65536`
- Attempting to dereference NULL gives `ldur x0 [x6, 0]` - hardware crash
	- Either because the positive num is too big or negative number is disallowed
